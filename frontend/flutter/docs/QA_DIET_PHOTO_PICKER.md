# 식단 사진 선택 수동 QA (#1433)

식단 추가 시트(`_DietAddSheet`)의 사진 입력은 플랫폼마다 다른 시스템 UI 로 열린다.
자동 테스트는 앱 쪽 분기(`MealPhotoChoiceLayout`)와 picker 인자까지만 확인하므로,
**시스템 UI 가 실제로 어떻게 뜨는지는 아래 절차로 실기기에서 본다.**

## 원·사각형 메뉴는 앱 결함이 아니다

iOS Safari 에서 사진 입력을 누르면 뜨는 **사진 보관함 / 사진 찍기 / 파일 선택** 메뉴와
그 원·사각형 모양은 브라우저가 `<input type="file" accept="image/*">` 에 그리는 시스템
UI 다. Flutter 위젯이 그린 것이 아니므로 레이아웃 버그로 조사하지 않는다.

- `image_picker_for_web` 은 보관함 선택을 `capture` 없는 파일 입력으로 연다.
- iOS Safari 는 이 입력의 메뉴 항목을 웹 표준 범위에서 숨길 수 없다.
- 그래서 웹에서는 앱이 `사진 추가` 한 갈래만 두고 선택을 이 메뉴에 맡긴다.

## 플랫폼별 기대 동작

| 환경 | 시트의 갈래 | 누른 뒤 |
| --- | --- | --- |
| 네이티브 iOS | `사진 선택` · `사진 찍기` | 사진 선택 → PHPicker(촬영 항목 없음), 사진 찍기 → 카메라 |
| 네이티브 Android | `사진 선택` · `사진 찍기` | 사진 선택 → 시스템 사진 선택기, 사진 찍기 → 카메라 |
| iOS Safari 웹 | `사진 추가` 하나 | 사진 보관함 / 사진 찍기 / 파일 선택 시스템 메뉴 |
| Android Chrome 웹 | `사진 추가` 하나 | 브라우저의 카메라·파일 선택 메뉴 |
| 데스크톱 브라우저 | `사진 추가` 하나 | 파일 선택 창 |

## 확인 절차

각 환경에서 식단 탭 → 식단 추가 시트를 열고 차례로 확인한다.

1. 시트에 위 표의 갈래만 보이고, 웹에서 `사진 찍기` 가 앱과 시스템 메뉴에 **두 번 나오지 않는다.**
2. 보관함에서 사진을 고르면 시트가 닫히고 분석 결과 시트로 넘어간다.
3. 촬영(네이티브 `사진 찍기`, 웹 시스템 메뉴의 `사진 찍기`)으로 찍은 사진도 같은 흐름으로 넘어간다.
4. 선택 창·카메라를 취소하면 오류 없이 식단 추가 시트에 머무른다.
5. 카메라·사진 권한을 거부하면 시트 안에 안내가 뜬다(iOS 네이티브 영구 거부는 설정 링크 포함).
6. 웹 `파일 선택` 으로 HEIC 등 서버가 받지 않는 형식을 고르면 형식 안내가 뜨고 업로드되지 않는다.

## 다시 확인해야 하는 때

- `pubspec.lock` 의 `image_picker_for_web`(현재 3.1.1) 또는 `image_picker_ios`
  (현재 0.8.13+6) 버전이 바뀔 때.
- 식단 추가 시트의 갈래 구성을 바꿀 때.
